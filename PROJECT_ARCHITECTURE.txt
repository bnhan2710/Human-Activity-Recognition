                        1. TỔNG QUAN HỆ THỐNG
================================================================================

Hệ thống nhận diện hoạt động người dùng theo thời gian thực sử dụng:
- Cảm biến IMU (MPU6050) trên ESP32
- AI/Machine Learning (CNN-GRU) để phân loại hoạt động
- Firebase để lưu trữ và đồng bộ dữ liệu
- Flutter Web App để hiển thị và giám sát

MỤC ĐÍCH:
- Theo dõi hoạt động vận động của người dùng (đi bộ, chạy, ngồi, đứng, lên/xuống cầu thang)
- Tính toán calo tiêu thụ
- Cảnh báo khi ngồi quá lâu (>1 phút)
- Thống kê lịch sử hoạt động theo ngày

HOẠT ĐỘNG NHẬN DIỆN:
1. WALKING - Đi bộ
2. RUNNING - Chạy
3. SITTING - Ngồi
4. STANDING - Đứng
5. UPSTAIRS - Lên cầu thang
6. DOWNSTAIRS - Xuống cầu thang

┌─────────────────────────────────────────────────────────────────────────────┐
│ A. PHẦN CỨNG (HARDWARE)                                                     │
└─────────────────────────────────────────────────────────────────────────────┘

1. ESP32 DevKit
   - Vi điều khiển: ESP32-WROOM-32
   - WiFi: 802.11 b/g/n
   - Bluetooth: BLE 4.2
   - CPU: Dual-core Xtensa 32-bit LX6
   - RAM: 520KB SRAM
   - Flash: 4MB
   - Ngôn ngữ: C/C++ (Arduino Framework)

2. MPU6050 (6-Axis IMU)
   - Accelerometer: ±2g, ±4g, ±8g, ±16g
   - Gyroscope: ±250, ±500, ±1000, ±2000 °/s
   - Interface: I2C
   - Sampling Rate: 20Hz (50ms interval)
   - Kalman Filter: Để làm mịn dữ liệu pitch/roll

SENSORS OUTPUT:
- ax_g, ay_g, az_g: Gia tốc 3 trục (g)
- gx_dps, gy_dps, gz_dps: Vận tốc góc 3 trục (độ/giây)
- amag_g: Độ lớn gia tốc tổng hợp
- pitch_kf, roll_kf: Góc pitch/roll sau Kalman filter

4. POST /predict/batch

   - Start Firebase listener
   - Listen to /sensor_data
   - Auto-predict and save

   - Stop Firebase listener

7. GET /firestore/predictions?user_id=user1&limit=10
   - Get predictions from Firestore

PREDICTOR.PY - AI Logic:

class ActivityPredictor:
    - __init__(model_path, artifacts_path)
    - load_model() → Load H5 model
    - load_artifacts() → Load scalers
    - preprocess(data) → Normalize, feature engineering
    - predict_window(window) → CNN-GRU prediction
    - predict_from_dataframe(df) → Batch prediction

MODEL ARCHITECTURE:
Input: (40, 9) - 40 timesteps, 9 features
├── Conv1D(64) + BatchNorm + ReLU + Dropout(0.3)
├── Conv1D(128) + BatchNorm + ReLU + Dropout(0.3)
├── GlobalMaxPooling1D
├── Bidirectional GRU(64) + Dropout(0.3)
├── Dense(32) + BatchNorm + ReLU + Dropout(0.3)
└── Dense(6, softmax) → Output probabilities

FIREBASE_HANDLER.PY - Firebase Operations:

class FirebaseHandler:
    - __init__(database_url, service_account_path)
    - connect() → Initialize Firebase Admin
    - start_listening(callback, path) → Listen to Realtime DB
    - save_prediction_to_firestore() → Save predictions
    - get_predictions_from_firestore() → Query predictions
    - save_notification_to_firestore() → Save notifications

DATA_BUFFER.PY - Sliding Window:

class DataBuffer:
    - window_size: 40 samples
    - overlap: 50% (20 samples)
    - add_sample(data) → Add to buffer
    - can_predict() → Check if buffer full
    - get_window() → Extract window for prediction

LUỒNG XỬ LÝ:
1. Firebase listener nhận dữ liệu mới
2. handle_firebase_data() được gọi
3. Thêm vào DataBuffer
4. Nếu đủ 40 samples:
   - Tính start_time, end_time, duration
   - Extract window
   - Preprocessing
   - CNN-GRU prediction
   - Save to Firestore (activity_predictions)
5. Log chi tiết (samples, prediction, probabilities)

                        5. LUỒNG DỮ LIỆU CHI TIẾT
================================================================================

┌─────────────────────────────────────────────────────────────────────────────┐
│ LUỒNG 1: TỪ CảM BIẾN ĐẾN DỰ ĐOÁN                                           │
└─────────────────────────────────────────────────────────────────────────────┘

BƯỚC 1: ESP32 đọc cảm biến (20Hz - 50ms)
├── MPU6050.getMotion6(&ax, &ay, &az, &gx, &gy, &gz)
├── Calculate amag = sqrt(ax² + ay² + az²)
├── Apply Kalman filter → pitch_kf, roll_kf
└── Buffer 10 samples (500ms)

BƯỚC 2: ESP32 gửi lên Firebase Realtime DB (2Hz - 500ms)
├── Firebase.setFloat("/sensor_data/ax_g", ax_g)
├── Firebase.setFloat("/sensor_data/ay_g", ay_g)
├── ...
└── Firebase.setInt("/sensor_data/timestamp", millis())

BƯỚC 3: FastAPI Backend nhận dữ liệu
├── Firebase listener triggered
├── handle_firebase_data(data) called
├── Extract sensor values
└── data_buffer.add_sample(data)

BƯỚC 4: Buffering (40 samples = 2 seconds)
├── Buffer size: 40 samples
├── Overlap: 50% (20 samples)
├── Check: data_buffer.can_predict()
└── If True → get_window()

BƯỚC 5: Preprocessing
├── window = data_buffer.get_window() → (40, 9)
├── Normalize with StandardScaler
├── Feature engineering (nếu cần)
└── Reshape for CNN-GRU: (1, 40, 9)

BƯỚC 6: AI Prediction
├── model.predict(window)
├── Output: probabilities (1, 6)
├── activity = argmax(probabilities)
├── confidence = max(probabilities)
└── Convert class index → activity name

BƯỚC 7: Calculate time info
├── Get window samples with timestamps
├── start_time = first_sample['timestamp']
├── end_time = last_sample['timestamp']
└── duration_seconds = (end_time - start_time) / 1000

BƯỚC 8: Save to Firestore
├── firebase_handler.save_prediction_to_firestore()
├── Collection: activity_predictions
├── Document: {
│     activity, confidence, probabilities,
│     user_id, start_time, end_time, duration_seconds,
│     created_at, timestamp
│   }
└── Return doc_id

BƯỚC 9: Log results
├── Print activity, confidence
├── Print probabilities (sorted)
├── Print samples used
└── Print Firestore doc_id

┌─────────────────────────────────────────────────────────────────────────────┐
│ LUỒNG 2: TỪ FIRESTORE ĐẾN FLUTTER UI                                       │
└─────────────────────────────────────────────────────────────────────────────┘

BƯỚC 1: Flutter listen Firestore (Real-time)
├── StreamBuilder<QuerySnapshot>
├── .collection('activity_predictions')
├── .where('user_id', isEqualTo: 'user1')
├── .orderBy('timestamp', descending: true)

└── .snapshots()

BƯỚC 2: Firestore push update (< 500ms)
├── New document added
├── Snapshot triggered
├── snapshot.docs.first.data()
└── Extract: activity, confidence, probabilities

BƯỚC 3: Update UI
├── setState() called
├── currentActivity = _translateActivity(activity)
├── confidence = confidence
├── probabilities = probabilities
└── UI rebuilds

BƯỚC 4: Translate activity
├── WALKING → Đi bộ
├── RUNNING → Chạy
├── SITTING → Ngồi
├── STANDING → Đứng
├── UPSTAIRS → Lên cầu thang
└── DOWNSTAIRS → Xuống cầu thang

BƯỚC 5: Display
├── Large activity icon
├── Activity name (Vietnamese)
├── Confidence bar (circular progress)
└── Probabilities breakdown

┌─────────────────────────────────────────────────────────────────────────────┐
│ LUỒNG 3: CẢNH BÁO NGỒI QUÁ LÂU                                             │
└─────────────────────────────────────────────────────────────────────────────┘

BƯỚC 1: ActivityMonitorService listen predictions
├── Singleton service initialized at app start
├── Listen to latest prediction (limit 1)
└── Real-time snapshots

BƯỚC 2: New prediction arrives
├── Extract: activity, duration_seconds, timestamp
├── Check if activity == 'SITTING'
└── If yes → handleSitting()

BƯỚC 3: Handle sitting
├── If NOT sitting before:
│   ├── Start sitting timer
│   ├── _sittingStartTime = now
│   ├── _totalSittingSeconds = duration_seconds
│   └── _hasNotifiedOneMinute = false
├── If already sitting:
│   └── _totalSittingSeconds += duration_seconds
└── Check threshold

BƯỚC 4: Check 1-minute threshold
├── if (_totalSittingSeconds >= 60)
├── AND (!_hasNotifiedOneMinute)
└── Then → _triggerSittingAlert()

BƯỚC 5: Trigger alert
├── Calculate duration
├── Create message: "Bạn đã ngồi hơn 1 phút..."
├── Save notification to Firestore:
│   FirebaseFirestore.instance
│     .collection('notifications')
│     .add({
│       user_id, title, message, type,
│       duration_minutes, is_read, created_at, timestamp
│     })
├── Call callback: onSittingAlert(message, duration)
└── Set _hasNotifiedOneMinute = true

BƯỚC 6: Show alert in UI
├── Alert dialog with title, message, icon
├── Buttons: "Đóng", "Xem thông báo"
├── SnackBar with "Xem" action
└── Navigate to NotificationsScreen

BƯỚC 7: Reset when activity changes
├── If activity != 'SITTING'
├── _resetSitting()
├── _totalSittingSeconds = 0
├── _hasNotifiedOneMinute = false
└── _sittingStartTime = null

┌─────────────────────────────────────────────────────────────────────────────┐
│ LUỒNG 4: THỐNG KÊ CALO VÀ LỊCH SỬ                                          │
└─────────────────────────────────────────────────────────────────────────────┘

BƯỚC 1: User chọn ngày
├── DatePicker (Vietnamese locale)
├── User selects date
└── setState → selectedDate

BƯỚC 2: Query Firestore
├── Get all predictions for user
├── No date filter in query (client-side filtering)
└── .snapshots() for real-time updates

BƯỚC 3: Client-side filtering
├── _filterByDate(docs)
├── Parse start_time for each doc
├── Check if date matches selectedDate
└── Return filtered list

BƯỚC 4: Calculate statistics
├── For each prediction:
│   ├── Extract activity, duration_seconds
│   ├── duration_minutes = duration_seconds / 60
│   ├── calorie_rate = caloriesPerMinute[activity]
│   ├── calories = calorie_rate × duration_minutes
│   ├── Accumulate:
│   │   ├── totalCalories += calories
│   │   ├── totalDuration += duration_seconds
│   │   ├── activityCalories[activity] += calories
│   │   └── activityDuration[activity] += duration_seconds
└── Return stats map

BƯỚC 5: Display (Calo Screen)
├── Summary card:
│   ├── Total calories (orange icon)
│   └── Total minutes (blue icon)
├── Activity breakdown:
│   ├── For each activity:
│   │   ├── Icon + name
│   │   ├── Duration (minutes)
│   │   └── Calories
│   └── Sorted by calories (descending)
├── Bar chart - Calories
└── Bar chart - Duration

BƯỚC 6: Display (History Screen - Pie Chart)
├── Calculate percentages:
│   └── percentage = (activity_duration / total_duration) × 100%
├── Pie chart sections:
│   ├── Color by activity
│   ├── Value = duration
│   ├── Title = percentage on chart
│   └── Radius = 100
└── Legend:
    ├── Activity icon + name
    ├── Duration formatted ("Xh Yp Zs")
    └── Percentage

PATH: /sensor_data

STRUCTURE:
{
  "ax_g": -0.02,          // float: Accelerometer X (g)
  "ay_g": 0.98,           // float: Accelerometer Y (g)
  "az_g": 0.15,           // float: Accelerometer Z (g)
  "gx_dps": 1.2,          // float: Gyroscope X (deg/s)
  "gy_dps": -0.5,         // float: Gyroscope Y (deg/s)
  "gz_dps": 0.3,          // float: Gyroscope Z (deg/s)
  "amag_g": 1.01,         // float: Magnitude (g)
  "pitch_kf": 5.2,        // float: Kalman-filtered pitch (deg)
  "roll_kf": 2.8,         // float: Kalman-filtered roll (deg)
  "timestamp": 1699876543210  // long: Milliseconds since epoch
}

FREQUENCY: 2 updates/second (500ms interval)
SIZE: ~200 bytes per sample
RETENTION: Overwrite (only latest sample kept)

INDICES: None (single path, overwrite mode)

┌─────────────────────────────────────────────────────────────────────────────┐
│ B. CLOUD FIRESTORE                                                          │
└─────────────────────────────────────────────────────────────────────────────┘

COLLECTION 1: activity_predictions
-----------
DOCUMENT STRUCTURE:
{
  "activity": "SITTING",                    // string: Activity name
  "confidence": 0.95,                       // float: 0.0 - 1.0
  "probabilities": {                        // map<string, float>
    "SITTING": 0.95,
    "STANDING": 0.03,
    "WALKING": 0.01,
    "RUNNING": 0.005,
    "UPSTAIRS": 0.003,
    "DOWNSTAIRS": 0.002
  },
  "user_id": "user1",                       // string: User identifier
  "start_time": "2024-11-15T10:30:43.000",  // string: ISO 8601
  "end_time": "2024-11-15T10:30:45.000",    // string: ISO 8601
  "duration_seconds": 2.0,                  // float: Duration in seconds
  "created_at": "2024-11-15T10:30:45.123",  // string: ISO 8601
  "timestamp": Timestamp                     // Firestore Timestamp (server)
}

INDICES REQUIRED:
1. user_id (Ascending) + timestamp (Descending)
   - For: .where('user_id', '==', 'user1').orderBy('timestamp', descending: true)

FREQUENCY: ~1 document every 2 seconds (when prediction made)
SIZE: ~300 bytes per document
RETENTION: Unlimited (or set TTL if needed)

QUERIES:
- Get latest: .where('user_id', '==', 'user1').orderBy('timestamp', desc).limit(1)
- Get all for user: .where('user_id', '==', 'user1')
- Get by date range: Client-side filtering on start_time

COLLECTION 2: notifications
-----------
DOCUMENT STRUCTURE:
{
  "user_id": "user1",                       // string: User identifier
  "title": "Cảnh báo: Ngồi quá lâu!",      // string: Notification title
  "message": "Bạn đã ngồi hơn 1 phút. Hãy đứng dậy và vận động để tốt cho sức khỏe.",  // string
  "type": "sitting_alert",                  // string: Notification type
  "duration_minutes": 1,                    // int: Duration in minutes
  "is_read": false,                         // boolean: Read status
  "created_at": Timestamp,                  // Firestore Timestamp (server)
  "timestamp": "2024-11-15T10:35:20.000Z"  // string: ISO 8601
}

INDICES REQUIRED:
1. user_id (Ascending) + created_at (Descending)
   - For: .where('user_id', '==', 'user1').orderBy('created_at', desc)

NOTIFICATION TYPES:
- sitting_alert: Ngồi quá lâu (>1 phút)
- (Future: activity_goal, health_tip, system_notification)

FREQUENCY: ~1 notification per minute (when sitting alert triggered)
SIZE: ~250 bytes per document
RETENTION: Unlimited (or auto-delete after 30 days)

QUERIES:
- Get all for user: .where('user_id', '==', 'user1').orderBy('created_at', desc)
- Get unread: .where('user_id', '==', 'user1').where('is_read', '==', false)
- Mark as read: .doc(docId).update({'is_read': true})

COMMON ISSUES:

1. "Model not loaded"
   - Check model file path
   - Verify artifacts directory
   - Check TensorFlow version

2. "Firebase connection failed"
   - Verify serviceAccountKey.json
   - Check Firebase project settings
   - Verify network connectivity

3. "Insufficient data for prediction"
   - Need at least 40 samples (2 seconds)
   - Check buffer status: GET /buffer/status
   - Verify ESP32 is sending data

4. "Firestore index error"
   - Create required indices
   - Wait for index creation (can take minutes)
   - Check Firebase Console

5. "Slow Flutter updates"
   - Verify indexed queries
   - Use .limit(1) for latest prediction
   - Check network latency

6. "Sitting alert not working"
   - Check ActivityMonitorService initialized
   - Verify threshold: 60 seconds
   - Check notification permissions

Backend:
- Check terminal logs for predictions
- Verify Firebase listener status: GET /stream/status
- Check Firestore writes in Firebase Console

Flutter:
- Check browser console for errors
- Verify Firestore connection
